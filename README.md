## 源码与译文

`main` 分支保存构建与翻译源码、术语表和翻译缓存；`gh-pages` 分支用于发布生成的静态网站。原站通过 `upstream/` 子模块固定，图片在中文与英文页面之间共享，避免重复保存近 400 MB 资源。

`translations/titles.json` 保存 52 篇经代理核对的中文标题，`translations/glossary.json` 保存统一技术译名。按照维护者要求，专有名词以及难以准确汉译的词组保留原始英文，以每篇文章为范围，首次出现时在括号内用中文简短说明含义，后续继续使用英文。例如 `best-of-n（从 n 个候选中择优）`、`latent thoughts（潜在的思考过程）`、`harness（智能体运行框架）`。

全文由 GPT-6.1-sol 子代理直接生成，程序核对公式、代码及行内格式标记是否完整保留。译文属于机器初译，结构核验与主代理抽样语义核验不能替代每篇全文的人类审校。最终生成与审核结果将在验收完成后填写。

## 最短复核与本地构建

获取本站源码和固定版本原站：

```bash
git clone --recurse-submodules https://github.com/xingshuozhu1998/xingshuozhu1998.github.io.git
cd xingshuozhu1998.github.io
python3 -m pip install -r requirements.txt
python3 scripts/build.py extract
python3 scripts/build.py build
python3 scripts/check_site.py
```

`build.py` 只使用 Python 标准库，输出 `dist/`。验收脚本需要 `lxml`（用于解析网页并对比原文与译文的结构），将逐篇结果写入 `translations/validation.json`。验收成功的预期结果为 52 篇通过、错误数为 0、没有正文长段落整段漏译。缓存未完成时，构建结果会明确标注缺失段落；此时不应发布为完整中文版。

构建后的逐篇清单位于 `translations.json` 和 `dist/translations.json`，列出来源、源文件摘要、中文地址、英文地址、已译片段、缺失片段和机器初译状态。`complete` 字段只能说明翻译缓存覆盖完整，不能证明每段译文语义都正确。

## 翻译过程与更新

本次按维护者指定，使用三个 **GPT-6.1-sol 子代理**直接逐段翻译，分别负责 17、18、17 篇文章及公共页面片段。三个子代理独立写入分工缓存，维护者的主代理汇总后进行最终审核。生成译文不调用本机模型或外部翻译接口；构建和结构检查由本机 Python 脚本完成。

源文提取命令为：

```bash
python3 scripts/build.py extract
```

`translations/source.json` 的每项段落包含 `id`、`protected`、`placeholders` 和所在页面。`protected` 中的标记代表原公式、代码和 HTML 行内标签，真实内容保存在 `placeholders` 中。翻译时必须阅读真实公式，保持各标记字面内容、数量与先后顺序，并完整保留事实、数字、限定条件和引用。仅保持标记顺序不能证明数学含义准确，审核时还必须检查每个变量在原句与译句中的角色。

`translations/cache.json` 将段落 `id` 映射为实际中文译文。更新原文后，重新提取段落、翻译新增或变化的段落、运行构建和验收。构建时按照每篇文章的出现顺序，依据 `translations/english_terms.json` 保留英文术语及首次中文简释；目录、公式、代码和标签属性不占用正文的首次解释。参考文献保持英文论文题名，不在论文题名中插入术语括释。

## 验收边界

验收脚本检查每篇正文元素顺序、段落数量、公式原文、代码原文、正文图片文件、目录锚点、人工中文标题、长段落漏译，以及英文镜像的正文保留情况。所有检查均以固定提交的 `upstream/` 为依据。

结构核验通过后，仍需检查术语、数字、限定条件和推理是否忠于原文。本站会明确标为机器初译；译文由 GPT-6.1-sol 子代理直接生成；最终审核包含结构检查与语义检查，无法保证不存在所有翻译错误。本次最终核验结果将在构建完成后补充到这里。
